# Задание 15 — Проверка даты рождения и email

Форма принимает дату рождения и email, после чего данные сохраняются в базу данных.

Здесь проверки лучше разделить между frontend и backend.

## 1. Что проверять на frontend

На frontend можно сразу проверить:

* что дата рождения введена;
* что дата имеет правильный формат;
* что дата не находится в будущем;
* что email не пустой;
* что email имеет правильный формат.

Например, если пользователь ввел:

```text
Email: albina@
```

можно сразу показать ошибку:

```text
Введите корректный email.
```

Если дата рождения:

```text
31.15.2005
```

то нужно показать:

```text
Введите правильную дату рождения.
```

### Почему это нужно делать на frontend?

Пользователь сразу видит ошибку и может ее исправить, не отправляя каждый раз неправильные данные на сервер.

Но frontend-проверки недостаточно, потому что их можно обойти. Поэтому такие проверки обязательно нужны и на backend.

## 2. Что проверять на backend

Backend должен проверить данные еще раз перед сохранением в БД.

Нужно проверить:

* дата рождения существует и имеет правильный формат;
* дата рождения не находится в будущем;
* email имеет правильный формат;
* обязательные поля не пустые;
* email не превышает допустимую длину;
* email не занят, если он должен быть уникальным.

Например, если такой email уже есть в базе:

```text
albina@example.com
```

сервер не должен создавать вторую запись с таким же email.

Можно вернуть:

```http
409 Conflict
```

```json
{
  "error": "EMAIL_ALREADY_EXISTS",
  "message": "Этот email уже используется"
}
```

## 3. Почему backend тоже должен проверять данные?

Frontend нельзя считать безопасным местом для проверки данных. Пользователь может отправить запрос напрямую на сервер, не используя форму сайта.

Поэтому frontend нужен в основном для удобства пользователя, а backend — для правильности и безопасности данных перед сохранением в БД.

## 4. Как показывать ошибки

Ошибку лучше показывать рядом с тем полем, где она произошла.

Например:

```text
Дата рождения: 2030-05-10
                 ↓
Дата рождения не может быть в будущем.
```

И:

```text
Email: albina@
              ↓
Введите корректный email.
```

Если email уже существует:

```text
Email: albina@example.com

Этот email уже зарегистрирован.
Попробуйте войти или используйте другой email.
```

Также backend может вернуть несколько ошибок сразу:

```json
{
  "errors": {
    "birthDate": "Дата рождения не может быть в будущем",
    "email": "Введите корректный email"
  }
}
```

Frontend получает этот ответ и показывает каждую ошибку возле соответствующего поля.

## 5. Пример правильного сценария

Пользователь вводит:

```text
Дата рождения: 15.04.2005
Email: albina@example.com
```

Frontend проверяет данные. Если всё правильно, отправляет их на backend.

Backend снова проверяет данные и сохраняет их в базу данных.

Ответ:

```http
201 Created
```

```json
{
  "message": "Данные успешно сохранены"
}
```

## Итог

Frontend нужен для быстрой проверки и удобства пользователя.

Backend нужен для повторной проверки, безопасности и контроля данных перед записью в БД.

Ошибки лучше показывать рядом с конкретным полем, чтобы пользователь сразу понимал, что именно нужно исправить.
