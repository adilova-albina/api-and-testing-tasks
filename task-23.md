# Задание 23 - Загрузка списка данных

Экран frontend загружает список данных с сервера. Нужно предусмотреть разные состояния экрана, потому что запрос может выполняться долго, вернуть пустой результат или завершиться ошибкой.

## 1. Состояние загрузки

Когда запрос еще выполняется, пользователю нужно показать индикатор загрузки.

Например:

```text
Загрузка...
```

Можно использовать `CircularProgressIndicator` или skeleton.

При этом старый список можно оставить на экране, если пользователь просто обновляет данные.

## 2. Пустой результат

Если сервер успешно ответил, но список пустой, нужно показать отдельное сообщение.

Например:

```text
Список пока пуст.
```

Можно также добавить кнопку или подсказку, например:

```text
Список пока пуст.
Попробуйте изменить фильтр.
```

Это отличается от ошибки, потому что сервер ответил успешно.

## 3. Ошибка

Если запрос не удалось выполнить, нужно показать сообщение об ошибке.

Например:

```text
Не удалось загрузить данные.
Попробуйте еще раз.
```

И кнопку:

```text
[Повторить]
```

Пользователь сможет повторить запрос без перезапуска приложения.

## 4. Частичный результат

Иногда часть данных уже загрузилась, но дополнительный запрос завершился ошибкой.

В этом случае не нужно полностью очищать экран.

Например:

```text
Загруженные данные

1. Первый элемент
2. Второй элемент
3. Третий элемент

Не удалось загрузить остальные данные.

[Повторить]
```

Так пользователь продолжает видеть то, что уже успешно загрузилось.

## 5. Повторная загрузка

Если пользователь нажал «Повторить», нужно снова отправить запрос.

Во время повторного запроса можно показать небольшой индикатор загрузки, но уже загруженные данные желательно оставить на экране.

Если повторный запрос успешен, список обновляется.

Если снова произошла ошибка, показываем сообщение и оставляем возможность повторить запрос.

## 6. Как не показать устаревшие данные

Проблема может возникнуть при быстрой смене фильтра.

Например:

```text
Пользователь выбрал фильтр A
        ↓
Отправился запрос A
        ↓
Пользователь быстро выбрал фильтр B
        ↓
Отправился запрос B
```

Запрос B может закончиться раньше запроса A.

Если просто показывать результат каждого запроса, старый запрос A может прийти последним и заменить правильные данные для фильтра B.

### Решение

Каждому запросу можно присвоить номер или использовать `requestId`.

Например:

```text
requestId = 1 → фильтр A
requestId = 2 → фильтр B
```

Когда приходит ответ, приложение проверяет, является ли он результатом последнего запроса.

Если пришел ответ от `requestId = 1`, когда уже есть `requestId = 2`, такой ответ игнорируется.

Также можно отменять предыдущий HTTP-запрос при изменении фильтра, если используемая библиотека поддерживает отмену запросов.

## 7. Пример логики

```text
Выбран фильтр A
      ↓
Запрос A
      ↓
Выбран фильтр B
      ↓
Запрос A отменяется
      ↓
Запрос B
      ↓
Получены данные B
      ↓
Показать данные B
```

Таким образом, старый ответ не должен перезаписывать результат нового фильтра.

## Итог

Для экрана нужно предусмотреть как минимум следующие состояния:

* загрузка;
* успешная загрузка списка;
* пустой результат;
* ошибка;
* частичный результат;
* повторная загрузка.

Чтобы старые данные не отображались после быстрой смены фильтра, можно отменять предыдущий запрос или проверять `requestId` перед обновлением состояния экрана.
