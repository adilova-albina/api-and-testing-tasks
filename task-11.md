# Задание 11 -API для списка задач

Нужно сделать API, с помощью которого пользователь сможет работать со списком задач: создавать задачи, смотреть их, менять статус и удалять.

## Основные endpoints

| Метод  | URL                      | Что делает              |
| ------ | ------------------------ | ----------------------- |
| POST   | `/api/tasks`             | Создает новую задачу    |
| GET    | `/api/tasks`             | Показывает список задач |
| GET    | `/api/tasks/{id}`        | Показывает одну задачу  |
| PATCH  | `/api/tasks/{id}/status` | Меняет статус задачи    |
| DELETE | `/api/tasks/{id}`        | Удаляет задачу          |

## 1. Создание задачи

Используем `POST`.

### Запрос

```http
POST /api/tasks
Content-Type: application/json
```

```json
{
  "title": "Сделать SQL задание",
  "description": "Подготовить запросы для базы данных"
}
```

### Ответ

```http
201 Created
```

```json
{
  "id": 1,
  "title": "Сделать SQL задание",
  "description": "Подготовить запросы для базы данных",
  "status": "todo"
}
```

При создании новой задачи статус можно автоматически поставить `todo`.

## 2. Просмотр списка задач

Используем `GET`.

```http
GET /api/tasks
```

Ответ:

```http
200 OK
```

```json
{
  "items": [
    {
      "id": 1,
      "title": "Сделать SQL задание",
      "description": "Подготовить запросы для базы данных",
      "status": "todo"
    },
    {
      "id": 2,
      "title": "Подготовить презентацию",
      "description": "Сделать слайды для проекта",
      "status": "in_progress"
    }
  ]
}
```

## 3. Просмотр одной задачи

Чтобы получить конкретную задачу, передаем ее `id`.

```http
GET /api/tasks/1
```

Ответ:

```http
200 OK
```

```json
{
  "id": 1,
  "title": "Сделать SQL задание",
  "description": "Подготовить запросы для базы данных",
  "status": "todo"
}
```

## 4. Изменение статуса

Для изменения статуса можно использовать `PATCH`.

```http
PATCH /api/tasks/1/status
Content-Type: application/json
```

```json
{
  "status": "done"
}
```

Ответ:

```http
200 OK
```

```json
{
  "id": 1,
  "title": "Сделать SQL задание",
  "description": "Подготовить запросы для базы данных",
  "status": "done"
}
```

В данном API я использую три статуса:

```text
todo
in_progress
done
```

## 5. Удаление задачи

Для удаления используется `DELETE`.

```http
DELETE /api/tasks/1
```

Если задача была удалена:

```http
204 No Content
```

Тело ответа в этом случае не нужно.

## 6. Возможные ошибки

Основные коды ошибок:

| Код | Когда используется        |
| --- | ------------------------- |
| 200 | Запрос выполнен успешно   |
| 201 | Задача создана            |
| 204 | Задача удалена            |
| 400 | Неправильный запрос       |
| 404 | Задача не найдена         |
| 422 | Данные не прошли проверку |
| 500 | Ошибка на сервере         |

Например, если пользователь запросил задачу с `id=999`, которой нет:

```http
404 Not Found
```

```json
{
  "error": "TASK_NOT_FOUND",
  "message": "Задача не найдена"
}
```

Если при создании задачи не указано название:

```http
422 Unprocessable Entity
```

```json
{
  "error": "VALIDATION_ERROR",
  "message": "Название задачи обязательно"
}
```

## 7. Постраничная выдача

Если задач много, не стоит отправлять их все одним запросом. Для этого используется pagination.

Например:

```http
GET /api/tasks?page=2&limit=10
```

Здесь:

* `page=2` — вторая страница;
* `limit=10` — максимум 10 задач на странице.

Пример ответа:

```json
{
  "items": [
    {
      "id": 11,
      "title": "Задача 11",
      "status": "todo"
    },
    {
      "id": 12,
      "title": "Задача 12",
      "status": "done"
    }
  ],
  "pagination": {
    "page": 2,
    "limit": 10,
    "total": 25,
    "totalPages": 3
  }
}
```

Если всего 25 задач:

```text
1 страница → 1–10
2 страница → 11–20
3 страница → 21–25
```

## Итог

Таким образом, API позволяет создать, посмотреть, изменить статус и удалить задачу. Для большого количества задач используется постраничная выдача через `page` и `limit`. Для разных ошибок сервер возвращает соответствующие HTTP-коды.
