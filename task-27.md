# Задание 27 — Тестирование расчёта скидки

Нужно протестировать функцию, которая рассчитывает скидку в зависимости от суммы заказа.

Предположим, что скидка начинается с определенной суммы. Например:

```text id="n4h2xk"
Сумма заказа меньше 10 000 ₸ → скидки нет
Сумма заказа от 10 000 ₸ → скидка 10%
```

Основное внимание нужно уделить значениям около границы.

## 1. Граничные значения

Для тестирования я использую граничный анализ.

Если граница скидки находится на `10 000 ₸`, нужно проверить:

| Сумма заказа | Ожидаемый результат |
| -----------: | ------------------- |
|          0 ₸ | 0% скидки           |
|      9 999 ₸ | 0% скидки           |
|     10 000 ₸ | 10% скидки          |
|     10 001 ₸ | 10% скидки          |

Особенно важны значения `9 999`, `10 000` и `10 001`, потому что именно здесь может появиться ошибка в условии.

## 2. Обычные значения

Также нужно проверить обычные суммы:

```text id="q1n7cj"
5 000 ₸ → 0%
10 000 ₸ → 10%
15 000 ₸ → 10%
50 000 ₸ → 10%
```

При этом нужно проверить не только процент скидки, но и итоговую сумму.

Например:

```text id="y0a6ap"
Сумма: 20 000 ₸
Скидка: 10%

Размер скидки = 2 000 ₸
Итоговая сумма = 18 000 ₸
```

## 3. Некорректные значения

Нужно проверить некорректный ввод:

|           Значение | Ожидаемый результат |
| -----------------: | ------------------- |
|            `-1000` | Ошибка              |
|                `0` | Скидка 0%           |
|    Пустое значение | Ошибка              |
| Текст вместо числа | Ошибка              |

Отрицательная сумма заказа не должна использоваться для расчета скидки.

## 4. Unit-тесты

Так как расчет скидки является отдельной логикой, для нее удобно использовать unit-тесты.

Пример:

```dart id="q8y5pw"
test('discount is not applied below the limit', () {
  expect(calculateDiscount(9999), 0);
});

test('discount is applied at the limit', () {
  expect(calculateDiscount(10000), 10);
});

test('discount is applied above the limit', () {
  expect(calculateDiscount(10001), 10);
});
```

Также можно отдельно проверить итоговую сумму:

```dart id="j2r4kc"
test('final price is calculated correctly', () {
  expect(calculateFinalPrice(20000, 10), 18000);
});
```

## 5. Почему нужны граничные значения

Обычные значения могут работать правильно, но ошибка может находиться именно на границе условия.

Например, программист случайно написал:

```text id="6y4q9d"
amount > 10000
```

вместо:

```text id="a8x2kp"
amount >= 10000
```

В результате заказ ровно на `10 000 ₸` не получит скидку.

Поэтому значения до границы, на границе и после границы являются наиболее важными.

## Итог

Для тестирования расчета скидки я бы использовала **граничный анализ и unit-тесты**. Нужно проверить значения ниже, на границе и выше порога, а также обычные и некорректные значения. Это помогает найти ошибки в условиях расчета скидки.
