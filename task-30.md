# Задание 30 -Тестирование Flutter-экрана

Нужно протестировать Flutter-экран со списком данных. Основные случаи: загрузка, успешное отображение списка, пустой список, ошибка, поворот экрана и возвращение на экран после перехода на другую страницу.

## 1. Состояние загрузки

При первом открытии экрана данные еще не получены.

Проверяем:

```text id="w8j4xq"
Открыть экран
      ↓
Показать индикатор загрузки
      ↓
Отправить запрос
```

Ожидаемый результат:

* отображается `CircularProgressIndicator`;
* список не показывает неправильные или старые данные;
* после получения ответа индикатор исчезает.

## 2. Успешная загрузка списка

Если API возвращает данные, нужно проверить их отображение.

Например:

```text id="n6d2qa"
API → [Task 1, Task 2, Task 3]
```

Ожидаемый результат:

* отображаются все элементы;
* данные соответствуют ответу API;
* каждый элемент можно нажать, если предусмотрен переход на другой экран.

## 3. Пустой список

Если сервер вернул пустой список:

```json id="r8w4eu"
{
  "items": []
}
```

Не должно быть бесконечной загрузки.

Вместо этого нужно показать сообщение:

```text id="f3k9za"
Список пуст
```

Можно также добавить кнопку или действие для повторной загрузки.

## 4. Ошибка загрузки

Если API вернул ошибку или сеть недоступна, нужно проверить состояние ошибки.

Например:

```text id="c4p6xm"
Не удалось загрузить данные
[Повторить]
```

Проверяем, что:

* приложение не падает;
* пользователю показывается понятное сообщение;
* кнопка «Повторить» снова отправляет запрос.

## 5. Поворот экрана

Нужно проверить работу экрана после поворота устройства.

Например:

```text id="q7v1hs"
Открыть экран
      ↓
Загрузить список
      ↓
Повернуть устройство
      ↓
Проверить экран
```

Ожидаемый результат:

* приложение не падает;
* интерфейс перестраивается под новый размер;
* данные не должны неожиданно исчезать;
* не должно запускаться несколько одинаковых запросов без необходимости.

Если состояние экрана нужно сохранять, его необходимо правильно хранить в состоянии приложения.

## 6. Возвращение на экран

Проверяем переход на другой экран и возвращение обратно.

```text id="v5e2lk"
Список
  ↓
Открыть детали
  ↓
Вернуться назад
  ↓
Список
```

После возврата:

* приложение не должно падать;
* список должен отображаться корректно;
* не должно быть ошибки `setState() called after dispose()`;
* состояние экрана должно быть обработано правильно.

Если после изменения данных на странице деталей список должен обновиться, можно выполнить повторную загрузку после возвращения.

## 7. Пример тест-кейсов

| № | Сценарий                 | Ожидаемый результат           |
| - | ------------------------ | ----------------------------- |
| 1 | Открыть экран            | Показывается загрузка         |
| 2 | API вернул список        | Список отображается           |
| 3 | API вернул пустой список | Показывается сообщение        |
| 4 | API вернул ошибку        | Показывается ошибка           |
| 5 | Нажать «Повторить»       | Выполняется новый запрос      |
| 6 | Повернуть экран          | Экран продолжает работать     |
| 7 | Открыть детали           | Выполняется переход           |
| 8 | Вернуться назад          | Список отображается корректно |

## 8. Какие тесты использовать

Для такого экрана можно использовать несколько видов тестирования.

### Widget-тесты

Проверяют UI:

* loading;
* список;
* пустое состояние;
* ошибку;
* кнопку повторной загрузки.

### Unit-тесты

Можно отдельно протестировать логику загрузки данных и обработку разных состояний.

### Integration-тесты

Проверяют полный сценарий работы приложения:

```text id="q0h5az"
Открытие приложения
      ↓
Загрузка списка
      ↓
Переход в детали
      ↓
Возврат назад
```

Также можно проверить поведение при изменении ориентации устройства.
