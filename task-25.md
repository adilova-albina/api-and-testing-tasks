# Задание 25 - Flutter-экран списка

Нужно сделать Flutter-экран, который получает список данных из API. Пользователь должен иметь возможность обновить список свайпом и открыть подробную информацию об элементе.

## 1. Основные состояния экрана

Экран должен иметь несколько состояний:

```text id="8h8q2y"
Loading → загружаются данные
Success → данные загружены
Empty → список пустой
Error → произошла ошибка
```

Например, во время загрузки можно показать:

```text id="2j7qzv"
CircularProgressIndicator
```

Если данные успешно загрузились, показываем `ListView`.

Если список пустой:

```text id="1j5rhk"
Список пуст
```

Если произошла ошибка:

```text id="x5p7bd"
Не удалось загрузить данные
[Повторить]
```

## 2. Загрузка данных из API

Для работы с API можно использовать, например, `http` или `dio`.

Логику запроса лучше не писать прямо внутри `build()`.

Можно сделать отдельный класс для работы с API:

```dart
class TaskRepository {
  Future<List<Task>> getTasks() async {
    // GET /api/tasks
  }
}
```

Repository отвечает за получение данных, а UI только показывает результат.

## 3. Разделение UI и бизнес-логики

UI не должен самостоятельно выполнять всю работу с API.

Например, можно разделить приложение так:

```text
UI
 ↓
ViewModel / Controller
 ↓
Repository
 ↓
API
```

### UI

Отвечает за:

* отображение списка;
* индикатор загрузки;
* сообщение об ошибке;
* обработку нажатий.

### ViewModel / Controller

Отвечает за:

* состояние экрана;
* запуск загрузки;
* обновление списка;
* обработку ошибок.

### Repository

Отвечает за:

* запросы к API;
* получение данных;
* преобразование ответа сервера в модели.

Такой подход упрощает тестирование и изменение приложения.

## 4. Обновление свайпом

Для обновления списка можно использовать `RefreshIndicator`.

Пример:

```dart
RefreshIndicator(
  onRefresh: () async {
    await controller.loadTasks();
  },
  child: ListView.builder(
    itemCount: tasks.length,
    itemBuilder: (context, index) {
      return TaskItem(task: tasks[index]);
    },
  ),
)
```

Пользователь тянет список вниз, после чего выполняется новый запрос к API.

## 5. Переход в подробности

При нажатии на элемент списка можно открыть отдельный экран:

```dart
Navigator.push(
  context,
  MaterialPageRoute(
    builder: (_) => TaskDetailsPage(taskId: task.id),
  ),
);
```

Лучше передавать `id`, а подробную информацию получать на экране деталей из API.

## 6. Отмена запроса при уходе со страницы

Если экран закрывается во время загрузки, запрос желательно отменить.

Например, если используется `Dio`, можно использовать `CancelToken`.

Общая идея:

```text id="i0iwkd"
Открыли экран
      ↓
Начался запрос
      ↓
Пользователь ушел со страницы
      ↓
Запрос отменяется
```

Это позволяет не выполнять ненужную работу после ухода пользователя.

## 7. Как избежать обновления уничтоженного экрана

После завершения асинхронного запроса экран уже может быть закрыт.

Поэтому перед обновлением состояния нужно проверить, что `State` еще существует.

Например:

```dart
if (!mounted) return;

setState(() {
  tasks = result;
});
```

Если `mounted == false`, значит экран уже удален из дерева Flutter и обновлять его нельзя.

## 8. Общая схема

```text id="l8km3f"
Открытие экрана
       ↓
Показать Loading
       ↓
Запрос к API
       ↓
Получить данные
       ↓
Показать список
       ↓
Пользователь делает свайп
       ↓
Повторный запрос
       ↓
Обновить список
```

Если пользователь уходит со страницы во время запроса:

```text id="0bxz9n"
Запрос выполняется
       ↓
Пользователь ушел
       ↓
Отменить запрос
       ↓
Не обновлять уничтоженный экран
```

## Итог

Для такого Flutter-экрана лучше разделить UI, логику состояния и работу с API.

Для обновления списка используется `RefreshIndicator`, для перехода — `Navigator`, а для безопасной работы с асинхронными запросами нужно отменять ненужные запросы и проверять `mounted` перед обновлением состояния.
